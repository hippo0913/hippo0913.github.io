# 精读官方文档：Claude Code 如何工作

> 💬 hippo：理解 Claude Code 的工作原理，能帮你预判它的行为、写出更有效的提示词、知道什么时候该信任它、什么时候要小心。

---

## 一、这个功能是什么

Claude Code 是一个在终端中运行的**代理助手**。虽然它在编码方面表现出色，但它可以帮助你从命令行执行的任何操作：编写文档、运行构建、搜索文件、研究主题等。

它不是"代码补全工具"，而是**代理编码工具**：

| 特性 | 代码补全 | 代理编码（Claude Code） |
|------|---------|------------------------|
| **触发方式** | 你打字它补全 | 你说目标它执行 |
| **输入** | 当前文件上下文 | 整个代码库 + 历史对话 |
| **输出** | 代码片段 | 完整的任务执行 |
| **能力** | 写代码 | 读代码、写代码、跑命令、调试 |

> 💬 hippo：这个区别很关键——你给它**目标**，不是**步骤**。让 Claude 自己决定用什么工具、怎么组合。

## 二、官方教程精读

### 2.1 代理循环

当你给 Claude 一个任务时，它会经历三个阶段：**收集上下文**、**采取行动**和**验证结果**。这些阶段相互融合。

```
┌─────────────────────────────────────────────────────────┐
│                      代理循环                            │
│                                                         │
│   你的提示 → 收集上下文 → 采取行动 → 验证结果 → 完成？    │
│                 ↑                        │              │
│                 └──────── 否 ────────────┘              │
│                                                         │
│   你可以随时中断                                         │
└─────────────────────────────────────────────────────────┘
```

循环会根据你的要求进行调整：
- 关于代码库的问题可能只需要**收集上下文**
- 错误修复会循环通过**所有三个阶段**多次
- 重构可能涉及**广泛的验证**

Claude 根据从前一步学到的内容决定每一步需要什么，将数十个操作链接在一起并沿途进行纠正。

> 💬 hippo：你也是这个循环的一部分。你可以随时中断以引导 Claude 朝不同方向发展、提供额外的上下文或要求它尝试不同的方法。

### 2.2 模型

Claude Code 使用 Claude 模型来理解你的代码并推理任务。Claude 可以：
- 读取任何语言的代码
- 理解组件如何连接
- 找出需要改变什么来实现你的目标
- 对于复杂任务，将工作分解为步骤并执行

**可用模型：**

| 模型 | 特点 | 适用场景 |
|------|------|---------|
| **Sonnet** | 平衡速度和质量 | 大多数编码任务 |
| **Opus** | 更强的推理能力 | 复杂的架构决策 |

```bash
# 会话中切换模型
/model

# 启动时指定模型
claude --model opus
```

### 2.3 内置工具

工具是使 Claude Code 成为代理的原因。没有工具，Claude 只能用文本回应。有了工具，Claude 可以采取行动：读取代码、编辑文件、运行命令、搜索网络。

**五大工具类别：**

| 类别 | Claude 可以做什么 |
|------|------------------|
| **文件操作** | 读取文件、编辑代码、创建新文件、重命名和重新组织 |
| **搜索** | 按模式查找文件、使用正则表达式搜索内容、探索代码库 |
| **执行** | 运行 shell 命令、启动服务器、运行测试、使用 git |
| **网络** | 搜索网络、获取文档、查找错误消息 |
| **代码智能** | 编辑后查看类型错误和警告、跳转到定义、查找引用（需要代码智能插件） |

**工具使用示例：**

当你说"修复失败的测试"时，Claude 可能会：

```
1. 运行测试套件以查看失败的内容（执行）
2. 读取错误输出（搜索）
3. 搜索相关的源文件（搜索）
4. 读取这些文件以理解代码（文件操作）
5. 编辑文件以修复问题（文件操作）
6. 再次运行测试以验证（执行）
```

每个工具使用都会给 Claude 新的信息，告知下一步。这就是代理循环的实际应用。

### 2.4 Claude 能访问什么

当你在目录中运行 `claude` 时，Claude Code 可以访问：

| 来源 | 内容 |
|------|------|
| **你的项目** | 目录和子目录中的文件，以及你允许的其他地方的文件 |
| **你的终端** | 你可以运行的任何命令：构建工具、git、包管理器、系统实用程序 |
| **你的 git 状态** | 当前分支、未提交的更改和最近的提交历史 |
| **CLAUDE.md** | 存储 project-specific 说明、约定和上下文 |
| **自动内存** | Claude 自动保存的学习内容，MEMORY.md 的前 200 行在每个会话开始时加载 |
| **配置的扩展** | MCP servers、skills、subagents、Claude in Chrome |

> 💬 hippo：因为 Claude 看到你的整个项目，它可以跨文件工作。当你说"修复身份验证错误"时，它会搜索相关文件、读取多个文件、协调编辑、运行测试验证。这与只看到当前文件的内联代码助手不同。

### 2.5 执行环境

Claude Code 在三个环境中运行：

| 环境 | 代码运行位置 | 用例 |
|------|-------------|------|
| **本地** | 你的机器 | 默认。完全访问你的文件、工具和环境 |
| **云** | Anthropic 管理的虚拟机 | 卸载任务、处理你本地没有的仓库 |
| **远程控制** | 你的机器，从浏览器控制 | 使用网络 UI，同时保持一切本地 |

### 2.6 会话管理

Claude Code 在你工作时将对话保存在本地。每条消息、工具使用和结果都被存储。

**会话特点：**
- **会话是独立的**：每个新会话都以新的上下文窗口开始，没有来自以前会话的对话历史
- **自动快照**：在 Claude 进行代码更改之前，它会对受影响的文件进行快照

**恢复和分叉会话：**

```bash
# 恢复会话（继续相同会话）
claude --continue
claude --resume

# 分叉会话（创建新会话，保留历史）
claude --continue --fork-session
```

```
┌─────────────────────────────────────────┐
│            会话连续性                    │
│                                         │
│   原始会话 ──────────────────→ 恢复     │
│       │                         (相同ID) │
│       │                                  │
│       └─── 分叉 ────────────→ 新会话    │
│                               (新ID)    │
└─────────────────────────────────────────┘
```

**跨分支工作：**
- Claude 看到你当前分支的文件
- 切换分支时，对话历史保持不变
- 可以通过 git worktrees 运行并行 Claude 会话

### 2.7 上下文窗口

Claude 的上下文窗口保存你的对话历史、文件内容、命令输出、CLAUDE.md、加载的 skills 和系统说明。

**当上下文填满时：**
- Claude Code 自动管理上下文
- 首先清除较旧的工具输出
- 然后在需要时总结对话
- 你的请求和关键代码片段被保留

```bash
# 查看什么在占用空间
/context

# 手动压缩
/compact

# 带焦点的压缩
/compact focus on the API changes
```

> 💬 hippo：将持久规则放在 CLAUDE.md 中，而不是依赖对话历史。对话早期的详细说明可能会在压缩时丢失。

**使用 Skills 和 Subagents 管理上下文：**

| 功能 | 如何帮助 |
|------|---------|
| **Skills** | 按需加载。描述在会话开始时加载，完整内容仅在使用时加载 |
| **Subagents** | 获得自己的新上下文，完全独立于主对话。他们的工作不会使你的上下文膨胀 |

### 2.8 检查点和权限

Claude 有两个安全机制：检查点让你撤销文件更改，权限控制 Claude 可以做什么。

**检查点：**
- 每个文件编辑都是可逆的
- 在 Claude 编辑任何文件之前，它会对当前内容进行快照
- 如果出现问题，按两次 `Esc` 回退

> ⚠️ 检查点仅涵盖文件更改。影响远程系统（数据库、API、部署）的操作无法进行检查点。

**权限模式（按 Shift+Tab 切换）：**

| 模式 | 说明 |
|------|------|
| **默认** | Claude 在文件编辑和 shell 命令之前询问 |
| **自动接受编辑** | Claude 编辑文件而不询问，仍然询问命令 |
| **Plan Mode** | Claude 仅使用只读工具，创建你可以在执行前批准的计划 |

```json
// .claude/settings.json 中允许特定命令
{
  "permissions": {
    "allow": [
      "Bash(npm test)",
      "Bash(git status)"
    ]
  }
}
```

## 三、hippo 的实战经验

> 💬 hippo：以下是我实际使用中的经验：

### 3.1 上下文管理的艺术

我踩过最大的坑就是"让它一直做"，结果上下文满了之后开始胡言乱语。

**我的经验：**

1. 完成一个大功能后，主动 `/clear` 重启
2. 重启前让它写个进度总结到 `.md` 文件
3. 新 session 读这个文件继续
4. 定期运行 `/context` 检查上下文使用情况

### 3.2 给指令的艺术

| 差的指令 | 好的指令 |
|---------|---------|
| "优化代码" | "把这个 O(n²) 的排序改成 O(n log n)" |
| "修复 bug" | "修复 login.ts 第 42 行的 TypeError，应该是 undefined 检查缺失" |
| "添加功能" | "在用户注册时发送欢迎邮件，用现有的 mailer 服务" |

> 💬 hippo：你的初始提示越精确，你需要的更正就越少。参考特定文件、提及约束、指出示例模式。

### 3.3 中断和引导

你可以随时中断 Claude。如果它走错了路：
1. 直接输入你的更正
2. 按 Enter
3. Claude 会停止正在做的事情并根据你的输入调整

不需要等待它完成或重新开始。

### 3.4 委派而非指示

想象委派给一个有能力的同事。提供上下文和方向，然后相信 Claude 会弄清楚细节：

```markdown
> 对于持卡人过期的用户，结账流程已损坏。
> 相关代码在 src/payments/ 中。你能调查并修复它吗？
```

你不需要指定要读取哪些文件或运行什么命令。Claude 会弄清楚。

### 3.5 什么时候要小心

- 涉及生产环境配置
- 删除操作
- 数据库迁移
- 安全相关代码

这些场景建议：
1. 先用 `--permission-mode plan` 让它规划
2. 仔细审查计划
3. 确认后再执行

## 四、常见问题

**Q: Claude 记得之前 session 的一切吗？**

A: 不，每个 session 独立。要跨 session 持久化，使用 CLAUDE.md 或自动内存。

**Q: 给它越多文件越好吗？**

A: 不，给它**相关**的文件，不是**所有**的文件。太多无关内容会消耗上下文、降低准确度。

**Q: Claude 会犯错吗？**

A: 会，而且犯错后可能一本正经坚持错误答案。重要操作要验证。

**Q: 如何减少 token 消耗？**

A: 1) 使用 subagents 隔离大任务；2) 设置 skills 的 `disable-model-invocation: true`；3) 定期 `/compact`。

## 五、小结

Claude Code 工作原理：

| 概念 | 一句话 |
|------|--------|
| 代理循环 | 收集上下文 → 采取行动 → 验证结果 → 重复直到完成 |
| 工具系统 | 五类工具（文件、搜索、执行、网络、代码智能）让它能做事 |
| 会话管理 | 独立会话，可恢复或分叉，跨分支工作 |
| 上下文窗口 | 自动压缩，用 CLAUDE.md 存持久规则 |
| 安全机制 | 检查点撤销文件更改，权限模式控制操作 |

**核心心法**：给目标而非步骤，管理好上下文，敏感操作要验证。
