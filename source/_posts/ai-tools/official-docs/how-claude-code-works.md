# 精读官方文档：Claude Code 如何工作

> 💬 hippo：理解 Claude Code 的工作原理，能帮你预判它的行为、写出更有效的提示词、知道什么时候该信任它、什么时候该小心。

---

## 核心概念：代理 vs 补全

Claude Code 不是"代码补全工具"，而是**代理编码工具**。

| 特性 | 代码补全 | 代理编码（Claude Code） |
|------|---------|------------------------|
| **触发方式** | 你打字它补全 | 你说目标它执行 |
| **输入** | 当前文件上下文 | 整个代码库 + 历史对话 |
| **输出** | 代码片段 | 完整的任务执行 |
| **能力** | 写代码 | 读代码、写代码、跑命令、调试 |

> 💬 hippo：这个区别很关键——你给它**目标**，不是**步骤**。让 Claude 自己决定用什么工具、怎么组合。

## 工作流程：四个阶段

### 1. 读取上下文

Claude Code 启动时，会读取：

| 来源 | 内容 |
|------|------|
| `CLAUDE.md` | 项目指令、编码规范、常见工作流 |
| 文件系统 | 当前目录结构、相关文件内容 |
| 历史对话 | 本次会话的上下文 |

```bash
# Claude 看到的上下文示例
project/
├── CLAUDE.md          # "使用 2 空格缩进"
├── package.json       # 依赖和脚本
├── src/
│   └── index.ts       # 代码内容
└── tests/
    └── index.test.ts  # 测试文件
```

> 💬 hippo：这就是为什么 CLAUDE.md 要保持简短——它在每次对话开始时都被加载，太长了消耗上下文、降低遵守度。

### 2. 理解任务

Claude 会分析你的请求：

```text
"修复登录页面的验证 bug"
```

Claude 会判断：

| 分析维度 | 结果 |
|---------|------|
| **任务类型** | 调试 → 修复 |
| **涉及文件** | `src/auth/login.ts`、`tests/login.test.ts` |
| **需要工具** | Read → Edit → Bash（运行测试） |
| **执行顺序** | 先读代码 → 定位 bug → 修复 → 验证测试 |

### 3. 规划执行

Claude 生成执行计划：

```
1. 读取 src/auth/login.ts
2. 搜索 "验证" 相关代码
3. 分析错误原因
4. 进行修改
5. 运行 npm test
6. 根据结果调整
```

> 💬 hippo：这个过程是自动的，但你可以要求它"先说计划再执行"，这样能提前发现问题。

```bash
# 进入计划模式
claude --permission-mode plan

# 或者用斜杠命令
/plan
```

### 4. 执行与反馈

Claude 执行每个步骤，并：

- **观察结果**：命令输出、测试结果、文件变化
- **调整策略**：遇到错误尝试修复
- **迭代优化**：直到任务完成或遇到阻塞

```
执行 → 观察 → 调整 → 重新执行 → ...
```

## 关键机制

### 上下文窗口

Claude 的上下文窗口有限：

| 模型 | 上下文窗口 |
|------|-----------|
| Haiku 4.5 | 约 200K tokens |
| Sonnet 4.6 | 约 200K tokens |
| Opus 4.6 | 约 200K tokens |

> 💬 hippo：200K tokens ≈ 15-20 万汉字。听起来很多，但如果读取整个代码库很快就用完。用 `/compact` 或 `/clear` 管理上下文。

**上下文管理技巧**：

| 命令 | 作用 |
|------|------|
| `/compact` | 压缩对话历史，释放上下文 |
| `/clear` | 清空对话，重新开始 |
| `/cost` | 查看当前会话 token 使用量 |

### 工具系统

Claude Code 通过工具与外界交互：

| 工具 | 用途 | 示例 |
|------|------|------|
| **Read** | 读取文件内容 | 看代码、配置文件 |
| **Write** | 创建新文件 | 写新组件、文档 |
| **Edit** | 修改现有文件 | 修复 bug、重构 |
| **Bash** | 执行 shell 命令 | 运行测试、安装依赖 |
| **Glob** | 搜索文件 | 找所有 `.ts` 文件 |
| **Grep** | 搜索内容 | 查找函数定义 |
| **Agent** | 启动子代理 | 并行处理独立任务 |

### 子代理（Subagents）

当任务复杂时，Claude 可以启动子代理：

```
主代理
├── 子代理 A：处理文档
├── 子代理 B：运行测试
└── 子代理 C：重构代码
```

**特点**：
- 子代理有独立的上下文
- 主代理协调多个子代理
- 适合并行处理独立任务

> 💬 hippo：子代理是"专职工人"——专门处理文档的、专门跑测试的。但别用得太滥，信息隔离会让主代理失去全局视角。

## 权限模式

Claude Code 提供多种权限模式：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **default** | 敏感操作需要批准 | 日常使用 |
| **acceptEdits** | 自动接受文件编辑 | 快速迭代 |
| **plan** | 只读，只做规划 | 复杂任务前期 |
| **auto** | 自动执行所有操作 | 高信任环境 |

```bash
# 启动时指定模式
claude --permission-mode acceptEdits

# 会话中切换
/permissions
```

## 常见误解

| 误解 | 真相 |
|------|------|
| ❌ "它记得之前 session 的一切" | ✅ 每个 session 独立，除非写了 CLAUDE.md 或进度文件 |
| ❌ "给它越多文件越好" | ✅ 给它**相关**的文件，不是**所有**文件 |
| ❌ "它不会犯错" | ✅ 会犯错，而且犯错后可能一本正经坚持错误答案 |
| ❌ "它只是代码补全" | ✅ 它是代理，能理解整个任务并主动执行 |

## hippo 的使用心得

### 上下文管理的艺术

> 💬 hippo：我踩过最大的坑就是"让它一直做"，结果上下文满了之后开始胡言乱语。

**我的经验**：

1. 完成一个大功能后，主动 `/clear` 重启
2. 重启前让它写个进度总结到 `.md` 文件
3. 新 session 读这个文件继续

### 给指令的艺术

| 差的指令 | 好的指令 |
|---------|---------|
| "优化代码" | "把这个 O(n²) 的排序改成 O(n log n)" |
| "修复 bug" | "修复 login.ts 第 42 行的 TypeError，应该是 undefined 检查缺失" |
| "添加功能" | "在用户注册时发送欢迎邮件，用现有的 mailer 服务" |

### 什么时候要小心

- **涉及生产环境配置**
- **删除操作**
- **数据库迁移**
- **安全相关代码**

这些场景建议：
1. 先用 `--permission-mode plan` 让它规划
2. 仔细审查计划
3. 确认后再执行

## 一句话总结

**Claude Code 工作流程：读取上下文 → 理解任务 → 规划执行 → 反馈迭代——理解这个循环，给目标而非步骤，管理好上下文，就能发挥最大价值。**
