## 开篇：为什么这篇文档值得精读

很多人拿到一个新工具，习惯性直接找"快速开始"或者"安装教程"。

我的习惯是先看 **概述（Overview）**。

原因很简单：如果你不知道这个工具能做什么、不能做什么、设计哲学是什么，后续学习会很痛苦——要么用得太浅，浪费能力；要么在不适用的场景强用，把自己搞得很沮丧。

这篇概述文档，就是帮你建立对 Claude Code 的**心智模型**。

## 核心概念：用大白话讲清楚

### 1. "代理"（Agentic）- 官方定义

根据官方文档，Claude Code 的定位非常清晰：

> **Claude Code 是一个代理编码工具（Agentic Coding Tool）**，可以读取你的代码库、编辑文件、运行命令，并与你的开发工具集成。可在终端、IDE、桌面应用和浏览器中使用。

几个关键词需要特别注意：

### 2. "代理"（Agentic）- 通俗解释

> 💬 hippo：这是最关键的概念。"代理"意味着它不是被动等你输入代码的补全工具，而是能主动理解目标、拆解任务、执行多步骤操作并自我纠错的 AI 协作者。
> 比如它就像是——你有个经验丰富的远程同事，可以自己看代码、自己改文件、自己跑测试，然后在需要时向你报告进度，而不是等你一步步告诉他该做什么。
> 在实际使用中，你通常会在这些场景遇到它：你让它"修复这个 bug"，它不会直接给你一段代码，而是自己去找相关文件、分析问题、尝试修复、运行测试，然后把结果告诉你。

它可以：
- 理解你的整个代码库（不只是当前文件）
- 跨多个文件和工具工作
- 自己执行命令、看结果、做调试
- 在任务之间传递上下文

### 3. "编码助手"vs"代码生成器"

> 💬 hippo：注意，是"助手"不是"替代"。它帮你构建功能、修复错误、自动化开发任务，但决策权和把关责任在你。
> 意思是：代码生成器——你给个函数签名，它返回代码；编码助手——你描述要解决的问题，它帮你找到文件、理解上下文、实现功能、运行测试。
> 我一开始以为它是 Copilot 那种自动补全，结果发现它完全可以自己动手做事，只是需要你确认。

### 4. "多平台" - 五种使用方式

Claude Code 不是单一形态的工具，而是有五种使用方式：

| 平台 | 使用场景 |
|------|----------|
| Terminal CLI | 命令行重度用户，完整功能 |
| VS Code | 集成在编辑器内，边写边问 |
| Desktop App | 独立桌面应用，专注对话 |
| Web | 浏览器访问，无需安装 |
| JetBrains IDEs | IntelliJ、PyCharm 等用户 |

> 💬 hippo：这很重要！因为这意味着你的配置（CLAUDE.md 文件、设置、MCP 服务器）在所有平台都是共享的。你在任何平台学习的东西，在其他平台都能用。
> 我主要用 Terminal CLI + VS Code。CLI 功能最完整，VS Code 适合快速问答和小型修改。

### 5. 前置要求

官方文档提到，大多数界面需要：
- **Claude 订阅** 或 **Anthropic Console 账户**
- Terminal CLI 和 VS Code 也支持**第三方提供商**

> 💬 hippo：第三方提供商指的是那些通过 API 兼容方式接入 Claude 模型的服务。如果你有企业需求或者想用其他渠道的 API，可以走这条路。
> 不过如果你只是个人使用，最简单的方式还是直接用 Claude 官方订阅，一个账户搞定所有平台。

## 实战指南：手把手教你用

### 场景 1：你习惯命令行工作

**问题背景**：
你大部分时间都在终端工作，习惯用键盘操作，不希望频繁切换到图形界面。

**解决步骤**：

1. **安装 Claude Code CLI**
   ```bash
   # macOS、Linux、WSL
   curl -fsSL https://claude.ai/install.sh | bash

   # Windows PowerShell
   irm https://claude.ai/install.ps1 | iex
   ```
   > 💬 hippo：注意这里的参数。`-fsSL` 很重要，`-f` 表示跟随重定向，`-sS` 表示在失败时静默输出，`-L` 表示支持 HTTPS。
   > 如果你是在 Windows CMD 下，还有一个对应的 `.cmd` 脚本。

2. **启动你的第一个会话**
   ```bash
   cd your-awesome-project
   claude
   ```

**预期效果**：
你会看到 Claude Code 欢迎屏幕，其中包含你的会话信息、最近的对话和最新更新。

> 💬 hippo：这是我最常用的方式。为什么？
> 1. 快捷：一个命令启动，不依赖其他工具
> 2. 通用：在任何支持 shell 的环境都能用
> 3. 轻量：不占用编辑器资源
> 唯一要注意的是：如果你用 VS Code 的其他插件（如 Copilot），可能会冲突。

### 场景 2：你主要在 VS Code 中工作

**问题背景**：
你已经在 VS Code 中开发，不希望频繁切换到终端，希望 AI 助手直接集成在编辑器里。

**解决步骤**：

1. **安装 VS Code 扩展**
   1. 打开 VS Code
   2. 按 `Cmd+Shift+X`（Mac）或 `Ctrl+Shift+X`（Windows/Linux）
   3. 搜索 "Claude Code"
   4. 点击安装
   5. 安装后按 `Cmd+Shift+P`（Mac）或 `Ctrl+Shift+P`（Windows/Linux）
   6. 输入 "Claude Code"
   7. 选择"在新标签页中打开"

**预期效果**：
Claude Code 会在 VS Code 右侧打开一个侧边栏，你可以直接在编辑器中与它对话。

> 💬 hippo：VS Code 集成的优势在于：
> - 可以看到内联代码差异，不用切换窗口
> - 支持 @-提及，快速引用代码片段
> - 有对话历史侧边栏，方便回顾
> 但要注意：如果你同时安装了多个 AI 插件，可能会有冲突。建议先禁用其他插件测试。

### 场景 3：你想要在不同设备间同步工作

**问题背景**：
你在办公室用电脑开始了一个任务，回家后想在笔记本上继续；或者你想在手机上查看任务进度。

**解决步骤**：

**Web 版访问**：直接访问 https://claude.ai/code

**Desktop 优势**：
- 独立窗口，不受浏览器限制
- 支持本地文件访问
- 可以后台运行长时间任务

> 💬 hippo：我主要在三种情况用 Web 版：
> 1. 在公司的受限环境，无法安装 CLI
> 2. 在手机或平板上快速查看任务进度
> 3. 与团队成员共享会话链接，协作讨论
> Desktop 应用我目前用得少，但如果你习惯独立应用，可以考虑。

### 场景 4：你使用 JetBrains IDE（IDEA、PyCharm 等）

**问题背景**：
你主要使用 IntelliJ IDEA、PyCharm、WebStorm 等 JetBrains 系列的 IDE。

**解决步骤**：

1. **安装 JetBrains 插件**
   1. 打开你的 IDE（如 IntelliJ IDEA）
   2. 进入 `File` → `Settings` → `Plugins`
   3. 搜索 "Claude Code"
   4. 安装并重启 IDE

**预期效果**：
Claude Code 会集成到你的 IDE 中，提供类似 VS Code 的体验。

> 💬 hippo：JetBrains 插件有个很棒的功能——**交互式差异查看**。
> 意思是：当 Claude Code 建议修改代码时，不是给你一大段文字，而是在 IDE 中显示差异视图。你可以：
> - 逐行查看变更
> - 选择接受或拒绝每一处修改
> - 保留你的代码风格和格式
> 这对于大项目的代码审查特别有用。

## hippo 的踩坑实录

### 坑点 1：安装后不知道怎么登录

**表现**：运行 `claude` 命令后，提示需要登录，但不知道用什么账户。

**原因**：官方文档说明了支持多种账户类型，但没有明确默认推荐哪个。

**解决**：

**推荐使用 Claude Pro 或 Max 订阅**（个人用户）：

```bash
# 首次启动时会自动提示登录
claude
# 按提示访问 claude.ai 完成授权
```

> 💬 hippo：为什么推荐 Pro/Max？
> 1. 统一订阅：一个账户同时支持 Claude Code 和网页版
> 2. 透明计费：有明确的使用额度和账单
> 3. 功能完整：所有平台和功能都能用
> Claude Console 也支持，但主要用于 API 调试和成本管理，不适合日常使用。

### 坑点 2：多个 AI 助手冲突

**表现**：同时安装了 Claude Code 和其他 AI 插件（如 GitHub Copilot），编辑器变得卡顿或响应奇怪。

**原因**：多个 AI 助手同时监听编辑器事件，可能互相干扰。

**解决**：

**建议方案**（按优先级）：

1. **只保留一个**：根据你的工作需求选择一个主力工具
2. **按项目切换**：某些项目用 A，某些项目用 B
3. **使用功能隔离**：VS Code 的 Workspace 功能

> 💬 hippo：我的经验是——不要贪多。
> 我试过同时用 Claude Code + Copilot + Codeium，结果是：
> - 编辑器变慢
> - AI 建议冲突（三个工具同时在改同一行代码）
> - 分不清是哪个工具的输出
> 现在的策略是：主力用 Claude Code，需要特定功能时临时启用其他。

### 最佳实践总结

1. **先了解能力边界**：读完概述文档再动手
2. **从简单任务开始**：不要一上来就让 AI 重构整个项目
3. **保留人工决策权**：AI 建议后，你自己决定是否接受
4. **建立反馈循环**：用得越多，越知道怎么提问效果最好

## 常见问题解答

**Q: Claude Code 能离线使用吗？**

A: 不能。Claude Code 需要网络连接来调用 Claude API，但所有代码分析、文件操作都是本地进行的。

**Q: 我的代码会被上传到云端吗？**

A: 不会。Claude Code 只发送必要的上下文给 API，你的代码库保留在本地。但要注意：对话内容会被存储在你的 Claude 账户下，用于上下文记忆。

**Q: 可以在团队项目中使用吗？**

A: 可以。Claude Code 支持 Claude for Teams 和 Enterprise 订阅，团队成员使用各自的账户登录。每个成员的对话历史是独立的。

**Q: 哪个平台最适合新手？**

A: 我推荐 **Terminal CLI** 或 **VS Code 扩展**：
- Terminal：最原生的体验，学习成本最低
- VS Code：如果你已经在用 VS Code，集成最自然
