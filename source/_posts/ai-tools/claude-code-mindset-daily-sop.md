# Claude Code 日常 SOP：我的标准操作流程

前面几篇讲了 prompt 技巧、信任判断、踩坑经验。这篇把它们串起来，形成一个日常可以照着走的标准操作流程（SOP）。

这不是什么权威方法论，就是我用了几个月后沉淀下来的习惯。好用，所以分享出来。

<!-- more -->

---

## 开始新任务：3 件事

每次打开 Claude Code 开始新任务，我做三件事：

### 1. 确认目录

看一眼当前终端的工作目录是不是对的项目。听起来多余，但我真的在错误项目里干过活（翻车现场第 6 式）。

### 2. 一句话说清目标

```bash
claude "给用户列表加搜索功能，支持按姓名和邮箱模糊搜索"
```

或者如果已经在 Claude Code 会话里：

> 给用户列表加搜索功能，支持按姓名和邮箱模糊搜索。参考现有的分页实现。

注意这个 prompt 遵循了前面说的原则：目标明确 + 给参考 + 言简意赅。

### 3. 让 Claude 先读代码再动手

如果是修改现有代码：

> 先看一下当前的实现，告诉我你的修改计划，不要直接改代码。

这一步花 30 秒，但能避免 Claude 改了不该改的地方。它的修改计划也是你审查的依据。

## 任务执行中：检查点模式

我不让 Claude 一次性跑完所有步骤。而是用一个"检查点"循环：

```
Claude 做 3-5 步 → 我审查 → 确认或调整 → 下一轮
```

### 什么时候打断

- Claude 做了超过 5 步还没停下来检查 → 打断，看 diff
- Claude 开始修一个你没要求的东西 → 打断，确认是不是跑偏了
- Claude 陷入循环（搜索→编辑→测试→搜索→编辑→……）→ 打断，重新给方向

### 怎么审查

```bash
git diff  # 看整体改动范围
```

重点看：

1. 改了几个文件？应该改的都改了吗？不该改的动了吗？
2. 有没有删除我还在用的代码？
3. 新增的代码风格一致吗？

如果看起来没问题，说"继续"或"提交"。

## 事情不对劲时：升级路径

不是每次都能顺利推进。当遇到问题时，我按这个路径升级：

### Level 1：在当前会话里调整

Claude 的方向偏了一点，但还能救。

> 你改的方向不太对。我需要的是 X，不是 Y。回退刚才的改动，重新来。

大部分情况在这个级别就能解决。

### Level 2：`/clear` 重新开始

Claude 已经完全跑偏了，或者上下文太乱。

```bash
/clear
# 用更精确的 prompt 重新开始
```

### Level 3：检查 CLAUDE.md

Claude 反复犯同一个错误——比如总是用错误的错误码格式。

这时候不是 Claude 的问题，是你的规则没说清楚。把正确的做法写进 CLAUDE.md：

```markdown
# 新增规则
- 错误返回格式：`{"code": 40001, "message": "描述"}`
- 不要用 HTTP 状态码作为业务错误码
```

### Level 4：加 Hook

如果 Level 3 写了规则但 Claude 还是不遵守（比如总是忘记跑测试），就把它升级成 Hook：

```json
{
  "PreToolUse": [{
    "matcher": "git commit",
    "command": "cd /path/to/project && go test ./..."
  }]
}
```

Hook 是硬约束，不可能被跳过。

## 完成任务：3 步收尾

### 1. 审查最终 diff

```bash
git --no-pager diff
```

完整看一遍所有改动。这是最后一道防线。

### 2. 本地验证

根据任务类型做对应验证：

- 写了代码 → 跑测试
- 改了配置 → 本地启动验证
- 写了文章 → `hexo server` 预览

### 3. 提交

```bash
git add 具体文件
git commit -m "feat: 简短描述"
git push
```

提交信息保持简洁，说明"做了什么"而不是"怎么做的"。

---

## 每周维护：10 分钟

每周花 10 分钟做这些维护：

### 审查 CLAUDE.md

- 上周新增的规则还有必要吗？
- 有没有项目变更导致规则过时了？
- 总行数超过 200 行了吗？需要精简吗？

### 检查 Hooks

- 上周被触发了多少次？有误拦截吗？
- 有新的"必须强制执行"的规则需要加 Hook 吗？

### 清理残留

- 删掉不需要的临时文件
- 更新进度文件（如果有的话）

## SOP 速查卡

```
┌─────────────────────────────────────┐
│           开始新任务                  │
│  1. 确认目录                         │
│  2. 一句话说清目标                    │
│  3. 让 Claude 先读代码再动手          │
├─────────────────────────────────────┤
│           执行中                      │
│  检查点循环：Claude 做 3-5 步 → 审查  │
│  重点关注：文件范围 / 删除内容 / 风格  │
├─────────────────────────────────────┤
│           遇到问题                    │
│  L1 调整 prompt                      │
│  L2 /clear 重开                      │
│  L3 补 CLAUDE.md                     │
│  L4 加 Hook                          │
├─────────────────────────────────────┤
│           完成收尾                    │
│  1. git diff 完整审查                 │
│  2. 本地验证                         │
│  3. 提交推送                         │
└─────────────────────────────────────┘
```

这个 SOP 不复杂，但它让我避免了大部分常见的翻车场景。不需要每次都想着"接下来该干嘛"，照着走就行。
